**Owner-approved v2.19 (2026-11-03): remove extra P7 search-step deadline proof.** A real P7.2–P7.5 independent 300-second cold search is accepted by its measured elapsed search window (`300–301 s` including ordinary observation/scheduling overhead). No last-search-step completion timestamp or separate exact-deadline proof is required. This correction applies also to genuine historical runs that reported 300–301 s, without automatically granting a gate PASS: legal execution, live native↔2D causality, frozen 1,000 Stochastic fights, compatible reference and numeric DPS floor still apply. **Owner-approved v2.18 (2026-11-03): P7.5 final tolerance.** P7.5 requires `mean_DPS >= 0.93 * max(saved_reference_DPS, strongest_accepted_compatible_P7.1–P7.4_mean_DPS)` after the same genuine 300-second independent cold search and frozen 1,000-stochastic-fight native↔2D holdout. P7.1–P7.4 remain at `0.99 * saved_reference_DPS`. Do not waive source legality, accepted-prior compatibility, native/world causality or independent search. This supersedes v2.14's/v2.15's earlier 99% P7.5 language. See [P7](docs/gates/P7.md).

**Owner-approved v2.17 (2026-11-02): P2 solo-objective relevance.** Keep the full structurally reachable rank denominator and binary per-rank PASS/FAIL, but require executable behavioral proof only for talent effects that can affect the pinned solo-leveling objective (elapsed combat, pulls, movement, survival, resources or paid recovery). For a truly non-applicable effect, require explicit, source-backed and scenario-specific `DOES_NOT_AFFECT_SIM` justification and a check of the exclusion rather than implementing unrelated mechanics for a test. Mere lack of a DPS increase, an unsupported effect, or an optimizer not selecting a talent never establishes non-applicability. Legal point allocation and search reachability remain required for every rank. Do not add a full 100-mob or unrelated gameplay scenario per talent. See [P1–P2](docs/gates/P1-P2.md).

**Owner-approved v2.16 (2026-11-02): P5 paid breadth threshold.** Replace the old `N300 >= 10 × N30` condition with `N300 >= 2 × N30` for **unique genuinely paid source-legal complete configurations** in independent cold 30 s and 300 s searches of the same objective/source/space. This removes an over-strict throughput multiplier, not the 30/300 actual wall-time budgets, genuine 100-mob finalist/replay, talent-unlocked-action execution, same source/runtime or any P4/P6/P7 condition. See [P4–P6](docs/gates/P4-P6.md).

**Owner-approved v2.15 (2026-11-02): MythicSim reference fallback, no engine revalidation.** MythicSim Rust/Go is the project's accepted reference combat engine; do **not** make independent validation of MythicSim against an external ranking site or another engine a gate prerequisite. Where an exact external saved report exists (e.g. Druid L60 Balance), keep and compare against it. Where it does **not** exist for a checkpoint, create a **source-grounded reference build and rotation** from documented online Forever sources (Classic defaults where appropriate), starting with a level-60 build and deriving only legal, actually available abilities, talents, items and rotations at levels 40/30/20. Execute that frozen config with the selected genuine MythicSim engine to produce a pinned **native-generated reference result**, recording source links, build/APL, encounter and engine identity. Use that result as the reference for the checkpoint's P7.1–P7.5 comparisons under the same existing 1,000-stochastic-final, gate-specific tolerance (99% P7.1–P7.4; 93% P7.5), independent-search and live-2D execution rules. Label the reference as native-generated; never fabricate an external report ID or claim external parity. Missing external reports or extra proof that MythicSim is accurate are **not** blockers; actual missing source-legal inputs or executable behavior still are. See [P7](docs/gates/P7.md).

**Owner-approved v2.14 (2026-11-02): P7 validation and RNG.** P7.1–P7.5 internal independent cold searches evaluate actual source-legal configurations with deterministic **balanced RNG and few repetitions** for efficient, comparable optimization; they do not use expensive stochastic acceptance loops to rank candidates. After freezing the selected configuration, the final external-reference validation uses **1,000 genuine independent stochastic Rust/Go iterations** (live 2D↔native where required), evaluated by **arithmetic mean DPS**, with **1% shortfall allowed on P7.1–P7.4 and 7% on P7.5**. P7.1–P7.4 floor = `0.99 * saved_reference_DPS`; P7.5 independently frozen holdout floor = `0.93 * max(saved_reference_DPS, strongest_accepted_compatible_prior_P7.1–P7.4_DPS)`. The original saved request's iteration count is provenance, not a requirement to replay 10k. This overrides older P7-specific threshold/iteration language; P7 source legality, fixed reference config, native↔world causality, independent 300 s searches and 148×11 acceptance remain unchanged. See [P7](docs/gates/P7.md).

**Owner clarification (2026-11-02) — P7 sufficient final sample and tolerance:** **1,000 independent stochastic iterations are enough** for P7.1 final native and live 2D verification and P7.2–P7.5 frozen native/live holdouts. ## Acceptance contract

- The scoreboard has **148 checkpoints**: nine unrestricted classes × four levels (20, 30, 40, 60) = 36; Druid four profiles × four levels = 16; eight other classes × three profiles × four levels = 96. There is no L50 checkpoint.
- A checkpoint counts only when **P3–P6 and P7.1–P7.5** have each genuinely passed with mutually compatible source, ruleset and production-engine semantics. Acceptance can accumulate across separate runs; all gates need not pass in a single session or be rerun merely because unrelated commits landed. P3–P6 assess continuous **100-mob leveling**; P7 assesses a separate pinned MythicSim DPS-reference encounter. Never splice incompatible proofs.
- **No additional implicit gates.** Tests, metadata, compilation, static manifests, native-only diagnostics, partial evidence and green CI are not a substitute for the actual stated predicate. Report PASS/FAIL/BLOCKED truthfully. Preserve previously accepted owner-specific historical decisions and disclose their limits.
- Exact requirements and runtime authority:
  - [Common acceptance, engines, sources and transition](docs/gates/COMMON.md)
  - **Retired:** [P1–P2 historical contract](docs/gates/P1-P2.md) is retained for context only and is not an active acceptance gate.
  - [P3 gear smoke](docs/gates/P3.md)
  - [P4–P6 independent search and 100-mob comparison](docs/gates/P4-P6.md)
  - [P7.1–P7.5 MythicSim reference and live integration](docs/gates/P7.md)
- Stable on-demand CLI: `python tools/wf_gate.py --class <class> --level <level> --gate P3` (or P4–P6 or P7.1–P7.5). Actual production execution, not prewritten JSON, awards a new PASS; see [runtime contract](docs/gates/RUNTIME_AUTHORITY.md). Acceptance tests may be CLI/integration runs and need not be pytest unit tests.

## Delivery and evidence

1. Prioritize the smallest **material critical-path improvement** toward 148/148, not documents, run counts, checklists or status theater. Use the mutable work priority and actionable issues; parallelize independent code work.
2. Develop in an isolated branch. For a new/repaired gate, show **RED → GREEN → REFACTOR** against the *same* behavioral predicate; refactor shared mechanisms rather than implementing per-class exceptions, then rerun relevant cross-class/level regressions.
3. A passing **formal gate** requires **one real run** of the selected production code against the applicable approved gate predicate: source/ruleset/engine, inputs, measured effects, searches, comparisons and world causality are genuinely used where the gate requires them. The **persistent acceptance record may be only a gate-specific `PASS` and its timestamp**; optional run/commit links aid debugging but committed JSON, a `docs/evidence/` bundle, or a separate proof implementation is **not** mandatory. The test/production implementation remains executable for later revalidation. A timestamp cannot manufacture a PASS without the real successful run. Never mix incompatible runs or raise 0/148 on partial proof.
4. **Run once, retain PASS, revalidate only when materially invalidated.** Do not routinely repeat heavy 30s/300s/100-mob/holdout acceptance runs each hour, commit, PR or CI cycle; a different git SHA alone is not invalidation. If a changed source rule, affected production behavior, chosen engine, scenario or scoring semantics defeats the earlier test's relevance, rerun only the affected gate(s) and update their PASS timestamp upon success. Safe engineering changes may merge after appropriate **fast** regression tests without changing unrelated accepted gates. Record actionable failures, not reporting bureaucracy.
5. Use sourced Forever data and justified Classic defaults where Forever is unknown. Implement and test observable mechanics; don't require live-server measurement or speculative semantic-certification rounds. No invented game values, no hidden source completeness gates; see [common source rules](docs/gates/COMMON.md).
