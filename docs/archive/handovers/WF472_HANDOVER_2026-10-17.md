# WF472 — P-gate scenario applicability decisions

## User decision (2026-10-17)
In the **current** solo leveling / 100mob kill-recovery optimization scope:
- Druid Hibernate (source ID 2637): `DOES_NOT_AFFECT_SIM`.
- Druid Teleport: Moonglade (source ID 18960): `DOES_NOT_AFFECT_SIM`.

This is an acceptance-scope decision, **not a change to spell mechanics, ability legality, or the game engine**. Each exclusion records the scenario, source identity, reason and conditions for review. An excluded ability never counts as an executed ability or a PASS for its runtime behavior. Other legal damage, buff/debuff and CC abilities still need P1 coverage. Future P gates should reuse these explicit decisions when checking *the same simulation objective*, not independently reinvent them.

## What changed
- New `gate_config/p1_scenario_applicability_v1.json` (P-side explicit exclusions, no engine-specific spell branches).
- `tools/wf_gate_p1_live.py`: scenario-bound, class-key / spell-ID / name checked waiver ledger, `does_not_affect_sim` reported separately.
- `tools/wf_gate.py`: optional `--p1-scenario` argument with default `current_solo_leveling_100mob_v1`.
- Regression tests: unrelated classes, other levels, unknown scenarios, mismatched names, missing true combat actions still FAIL.

## Safety of interpretation
Current exemptions must be reviewed if the target/route scenario changes (e.g. Beast/Dragonkin crowd control becomes relevant or Moonglade travel is part of the route objective). Unknown scenarios are rejected rather than silently inheriting exclusions. This is deliberately a P-gate suitability decision, not a new spell whitelist in the simulator.
