Approved v2.10 predicates extracted from [PROCESS](../../PROCESS.md). **Owner update 2026-11-03 (PROCESS v2.18): P7.5's final mean-DPS floor is 93% of the larger accepted-compatible comparator; P7.1–P7.4 remain at 99%.** Apply the shared [engine and source constraints](COMMON.md). Do not treat historical owner-approved individual evidence as a general exemption.

**OWNER-APPROVED UPDATE (2026-11-02; supersedes older P7 thresholds).** Use **deterministic balanced RNG and a small, fixed repeat budget** for the internal, source-legal optimizer's candidate comparisons; the same seed/stream and scoring policy must make results reproducible and the low-repeat proxy never earns PASS. **After freezing a candidate** (or the fixed P7.1 reference) run **1,000 independent stochastic iterations** with the selected genuine native Rust/Go engine and live gsim-2D causality where required; the **arithmetic mean** of these final iterations decides the DPS floor, not the balanced-RNG search score or a 95% lower confidence bound. **P7.1–P7.4 permit a 1% DPS shortfall; P7.5 permits 7%:** P7.1–P7.4 require `DPS_final >= 0.99 * DPS_saved_reference`; P7.5's **independently frozen stochastic holdout** requires `DPS_final >= 0.93 * max(DPS_saved_reference, strongest_accepted_compatible_P7.1–P7.4_mean)`. Source and saved report configuration, legal APL/gear/talents, source/native↔world causality, 300 s independent cold search budgets, and compatible comparators remain mandatory. Original saved MythicSim request iteration counts remain identifiable historical metadata, **not a requirement to replay that many iterations**. No universal 10k-simulation rule and no percentage derived from number of iterations completed.

**Owner-approved correction (2026-11-03): remove the invented last-search-step deadline gate.** P7.2–P7.5 still require an independent, measured 300-second cold search. A real `300.000–301.000 s` elapsed wall-clock search receipt satisfies the search-window duration requirement; the one-second measurement/scheduling allowance is not additional optimizer budget. **Do not require, reconstruct or validate a separate last-search-step completion timestamp.** A legitimate previous 300–301 s production receipt is not invalidated solely because it lacks that extra timestamp. The selected native↔2D execution, compatible comparator, frozen 1,000-fight Stochastic final and each gate's DPS floor remain required.

### Reference availability: external if present, native-generated if absent (owner-approved 2026-11-02, PROCESS v2.15)

The source of this score is `native_generated_msim_reference`, **not** `external_saved_report`: a made-up external report ID, a synthetic DPS, or an unsupported proxy score is forbidden. Missing **external** report/Settings UI is never `REFERENCE_CONFIGURATION_MISSING` for this fallback. Missing **actual runnable source-legal build, native score or world execution** remains a real task/FAIL/BLOCKED as appropriate. **Scope of older external-only paragraphs below:** every demand for an exact saved external report ID, original report request, UI transcript or external saved ranking DPS applies **only when `external_saved_report` was selected because that report exists**. ### P7 — MythicSim reference, five independent tests (USER-REVISED 2026-10-28)

**The old P7 Decisions-challenger gate is replaced, not retained and not renamed P8.** P7 consists of the five required subgates P7.1, P7.2, P7.3, P7.4 and P7.5. A checkpoint has P7 PASS only if all five PASS with compatible source/engine and the *exact same pinned reference encounter*. `dsim` can remain an optional diagnostic challenger but is no longer mandatory for P7.

**Reference identity and fidelity (applies to P7.1–P7.5).** Pin the *saved* MythicSim ranking report ID and source URL, character class/spec/level/race, full gear/enchant/consumables/buffs/debuffs, talents, priority/rotation and its conditions, native engine/ruleset/source revision, iteration/seed policy, encounter duration/variation, target stats and baseline DPS. Do not substitute the live tier-list card or another saved report whose DPS changed later. If critical settings of the specified saved report cannot be obtained, the gate is **BLOCKED: REFERENCE_CONFIGURATION_MISSING**, not approximated by guessed presets or an invented number. If the report and our pinned runtime have irreconcilable rulesets or combat assumptions, give an actionable mismatch rather than falsifying equality.

**Saved report evidence (owner clarification 2026-11-02).** Accept either **the authenticated original saved MythicSim request recovered from that exact report ID** (with source report URL/ID and stable content hash), **or** a faithful field-by-field transcription of the same report's interactive Settings UI. The original request already records gear, enchants, talents, APL, buffs/debuffs, consumables and encounter: **no second UI capture is required** if that original request has already been pinned. Never substitute a guessed preset or another report. BLOCK only for an actual missing or conflicting *material* setting, naming the field and observed issue. The report's historical iteration count (10,000 in the saved Balance example) is metadata only and cannot constrain the new 1,000-iteration stochastic final or change the allowed 1% DPS shortfall.

**Production integration required (P7.1.3 and P7.2–P7.5; P7.1.2 is native diagnostic exception).** Every acceptance-scored production measurement runs OUR real `gsim` 2D world/controller interactively with one selected genuine pinned MythicSim **Rust (preferred) or Go** engine on one shared monotonic clock. gsim owns coordinates, facing/range, movement, CC and world effects; selected native engine owns combat/resource/cooldowns/buffs. World requests each boundary/ACK and native advances only to it; world state affects the next native decision. Commit a genuine world→native→world causal trace. Standalone `forever-engine sim` / `wowsimcli sim`, fixed coordinates without gsim, fake world or post-hoc replay FAIL/BLOCK live integration even at equal DPS.

**P7 DPS encounter world special case.** Model the saved MythicSim reference as a legal 2D scenario: a **level 63** stationary target that **does not attack the player** in the DPS benchmark, no adds, player begins at an optimal valid position for the chosen rotation (e.g. immediately in melee range or at the configured caster range), with **front/back explicitly selectable** and confirmed by the controller's coordinates and facing. No assumed closing travel is added when the reference has none. Use the report's actual encounter time distribution (the reference tier-list methodology defaults to about 120s ±15s) and all exact buffs, consumables, etc. If this world-side non-attacking target or front/back orientation does not causally determine selected Rust/Go engine behavior via the live handshake, FAIL. P7's **DPS** objective does not replace P4–P6's 100 consecutive-mob **seconds/mob** objective.

**Finite-target lethal semantics (P7.4 live world).** Preserve the source request's actual target Health; do not inflate HP to avoid a kill. If a gsim ACK reduces that target to zero, the coupled native fight legitimately ends at that lethal world boundary. A standalone native-only control has no world HP feedback and is therefore not an aggregate-DPS or first-duration comparator for lethal fights. P7.4 may classify that specific standalone-control divergence as non-comparable only when every per-fight target-health receipt is valid, the coupled native DPS equals the independently accumulated gsim world mean, the complete damage/ACK ledger balances, and the first-fight standalone duration still matches whenever the first world target survives. Nonlethal P7.4 candidates retain strict standalone native/world parity; P7.1 remains strict. The frozen P7.4 acceptance floor is scored on the coupled native result and gsim world mean, with the lethal-fight count and standalone-control comparability reported.

**P7.1 — Fixed reference reproduction; native baseline followed by engine-integration test.** Execute P7.1.1 → P7.1.2 → P7.1.3 in order. Gear, talents, rotation/APL and the saved encounter are fixed across both executions. All three steps are mandatory for P7.1 PASS; the native run does **not** substitute for the live 2D integration test.

**P7.1.1 — Saved reference configuration.** Record the exact saved report URL/ID, class/spec/level/race, items/enchants, talents/APL, buffs/debuffs/consumables, encounter/target/orientation/duration/variation, original seed and iteration metadata, available source/engine identity and reference DPS. **A report-ID-matched original request with known provenance and pinned hash satisfies the reference-settings evidence requirement; interactive Settings UI is an alternative, not an additional mandatory gate.** Verify the chosen Rust/Go and live-2D requests preserve these settings, except for using the approved 1,000 independent stochastic final iterations. Do not BLOCK solely for lack of a new UI screenshot or a 10k replay. Identify actual discrepancies when present.

**P7.1.2 — Native MythicSim Rust/Go reproduction (mandatory pre-integration diagnostic).** Execute exactly the P7.1.1 saved configuration (gear/enchants/talents/APL/buffs/debuffs/consumes/encounter) in **one real pinned Rust or Go native engine**, without gsim-2D. Rust is preferred, Go equally valid. Match source/ruleset/database, saved encounter/seed and stochastic scoring, using the **approved 1,000-iteration final count** rather than blindly replaying the historical request's iteration count. No optimization or invented substitutions. Require final 1,000-stochastic-iteration **native mean DPS >= 0.99 × pinned saved reference DPS**, with compatible statistical evaluation; publish full request/output, build/config hashes and combat metrics. Native success alone is not a new production P7.1 PASS.

**P7.1.3 — Live gsim-2D ↔ selected MythicSim Rust/Go reproduction (production acceptance).** Execute the same pinned config through real interactive gsim-2D↔selected native engine, ideally the same backend as P7.1.2. Demand final 1,000-stochastic-iteration **live mean DPS >= 0.99 × saved reference** with genuine causal world→native→world trace. If backend changes, rerun native comparison on the selected backend. No standalone, fake or post-hoc PASS.

**P7.1–P7.4 reference tolerance (owner-approved 2026-11-02); P7.5 93% (owner-approved 2026-11-03).** For the **independently discovered** winners of **P7.2, P7.3 and P7.4**, the minimum final 1,000-stochastic-iteration DPS is `DPS_winner >= 0.99 * DPS_external_reference` on the same pinned saved encounter, ruleset, native engine and scoring policy. The 1% margin applies to P7.1–P7.4, while P7.5 uses the owner-approved 7% margin; all 300-second independent cold searches, legality, production live 2D causality and complete measured evidence remain in force. **P7.1 requires >= 0.99 × the pinned reference on its original fixed configuration after 1,000 stochastic iterations.** **P7.5 uses 93% of BOTH the external reference and the strongest accepted-compatible prior, with the frozen 1,000-stochastic-fight holdout mean rather than a confidence lower bound.** This permission does not waive unproven runtime integration or endorse an over-budget run.

**Mandatory P7.5 non-inferiority acceptance (USER-REVISED 2026-10-30; issue #10).** The independently frozen P7.5 1,000-fight stochastic holdout **mean DPS** must reach **both** (a) at least **93% of the external saved MythicSim reference mean DPS** and (b) at least **93% of the strongest *accepted and compatible* P7.1–P7.4 independently measured stochastic mean DPS**, with the SAME pinned reference encounter, source/ruleset, native engine, target, duration distribution, buffs/debuffs, consumables and scoring policy. Do not select the comparator from an unaccepted diagnostic result or mix incompatible runs:

`mean_DPS_P7.5_frozen_holdout >= 0.93 * max(DPS_external_reference, max(mean_DPS_accepted_compatible_P7.1, ..., mean_DPS_accepted_compatible_P7.4))`.

Require an independently frozen stochastic holdout of **1,000 fights** with the selected genuine native Rust/Go engine's original **stochastic** RNG, separate from balanced-RNG search evaluation. **PASS/FAIL uses the frozen holdout *arithmetic mean DPS* against both floors — no one-sided 95% confidence-bound or p95 lower-bound PASS criterion.** Report standard deviation, standard error and confidence intervals if helpful for diagnostics, but they do **not** impose additional pass thresholds. Before establishing the strongest accepted-compatible prior, verify the accepted gate decision, frozen stochastic mean, fully source-legal gear/talents/APL and matching pinned engine/encounter/duration/buffs/consumes/RNG/scoring configuration; where prior results are incompatible, rerun the accepted prior winner with matched conditions and report the new provenance. **An unvalidated native-only candidate or unresolved legality/compatibility (for example PR #23's 797.362 DPS P7.4 result) cannot automatically become the P7.5 comparator; BLOCK comparator selection if unresolved.** Never change the winner or comparator after seeing P7.5 holdout. Rediscovering a prior winner independently is legal; seeding a cold search with a reference/prior winner is not. Internal P7.2–P7.5 candidate selection uses deterministic low-repeat balanced RNG. The 300-second cold-search budget and real live 2D↔native source/legal/causal requirements are unchanged. A below-floor holdout mean is FAIL; missing comparable accepted priors or missing required evidence is BLOCKED, never inferred PASS.
