# P7 — saved MythicSim reference, independent searches, live 2D

Approved v2.10 predicates extracted from [PROCESS](../../PROCESS.md). Apply the shared [engine and source constraints](COMMON.md). Do not treat historical owner-approved individual evidence as a general exemption.

**OWNER-APPROVED UPDATE (2026-11-02; supersedes older P7 thresholds).** Use **deterministic balanced RNG and a small, fixed repeat budget** for the internal, source-legal optimizer's candidate comparisons; the same seed/stream and scoring policy must make results reproducible and the low-repeat proxy never earns PASS. **After freezing a candidate** (or the fixed P7.1 reference) run **1,000 independent stochastic iterations** with the selected genuine native Rust/Go engine and live gsim-2D causality where required; the **arithmetic mean** of these final iterations decides the DPS floor, not the balanced-RNG search score or a 95% lower confidence bound. **All five P7 gates permit a 1% DPS shortfall:** P7.1–P7.4 require `DPS_final >= 0.99 * DPS_saved_reference`; P7.5's **independently frozen stochastic holdout** requires `DPS_final >= 0.99 * max(DPS_saved_reference, strongest_accepted_compatible_P7.1–P7.4_mean)`. Source and saved report configuration, legal APL/gear/talents, source/native↔world causality, 300 s independent cold search budgets, and compatible comparators remain mandatory. Original saved MythicSim request iteration counts remain identifiable historical metadata, **not a requirement to replay that many iterations**. No universal 10k-simulation rule and no percentage derived from number of iterations completed.

### P7 — MythicSim reference, five independent tests (USER-REVISED 2026-10-28)

**The old P7 Decisions-challenger gate is replaced, not retained and not renamed P8.** P7 consists of the five required subgates P7.1, P7.2, P7.3, P7.4 and P7.5. A checkpoint has P7 PASS only if all five PASS with compatible source/engine and the *exact same saved reference encounter*. `dsim` can remain an optional diagnostic challenger but is no longer mandatory for P7.

**Reference identity and fidelity (applies to P7.1–P7.5).** Pin the *saved* MythicSim ranking report ID and source URL, character class/spec/level/race, full gear/enchant/consumables/buffs/debuffs, talents, priority/rotation and its conditions, native engine/ruleset/source revision, iteration/seed policy, encounter duration/variation, target stats and baseline DPS. Do not substitute the live tier-list card or another saved report whose DPS changed later. If critical settings of the specified saved report cannot be obtained, the gate is **BLOCKED: REFERENCE_CONFIGURATION_MISSING**, not approximated by guessed presets or an invented number. If the report and our pinned runtime have irreconcilable rulesets or combat assumptions, give an actionable mismatch rather than falsifying equality.

**Saved report extraction and evidence (applies especially to P7.1.1).** The saved report URL and the settings visibly rendered in its own interactive UI are authoritative reference evidence. Do **not** make a raw API/JSON payload, byte-exact original request, internal endpoint, or automatic scraping a new acceptance prerequisite when all relevant settings can instead be read reliably in that UI. Read and record all applicable fields *from that exact saved report*: gear/items/enchants, talent ranks, rotation/APL and conditions, buffs/debuffs, consumables and their use, encounter/duration/iterations and other exposed settings. Manual faithful transcription, screenshots, and an audited structured transcription of the visible UI are acceptable; keep the report ID/URL, field-level provenance, extracted values and any ambiguities, then validate the translated selected Rust/Go request against this inventory. Never silently substitute a different race-comparison or tier-list preset, infer unknown values from DPS, or claim exact provenance for guessed settings. A text-only fetch returning "Fetching the saved simulation" or omitting JavaScript-rendered fields is **a limitation of that reader**, not evidence the report lacks settings. Try an interactive browser/UI route or another faithful capture method before declaring information unavailable. Mark `BLOCKED: REFERENCE_CONFIGURATION_MISSING` only when a *material required setting actually cannot be determined after reasonable extraction attempts*; name the specific unknown fields and the attempted routes. Do not falsely claim settings have been extracted if the UI was not examined. This rule changes **source acquisition**, not the P7.1.2 native or P7.1.3 live acceptance standards; raw payload retrieval is optional supporting evidence.

**Production integration required (P7.1.3 and P7.2–P7.5; P7.1.2 is native diagnostic exception).** Every acceptance-scored production measurement runs OUR real `gsim` 2D world/controller interactively with one selected genuine pinned MythicSim **Rust (preferred) or Go** engine on one shared monotonic clock. gsim owns coordinates, facing/range, movement, CC and world effects; selected native engine owns combat/resource/cooldowns/buffs. World requests each boundary/ACK and native advances only to it; world state affects the next native decision. Commit a genuine world→native→world causal trace. Standalone `forever-engine sim` / `wowsimcli sim`, fixed coordinates without gsim, fake world or post-hoc replay FAIL/BLOCK live integration even at equal DPS.

**P7 DPS encounter world special case.** Model the saved MythicSim reference as a legal 2D scenario: a **level 63** stationary target that **does not attack the player** in the DPS benchmark, no adds, player begins at an optimal valid position for the chosen rotation (e.g. immediately in melee range or at the configured caster range), with **front/back explicitly selectable** and confirmed by the controller's coordinates and facing. No assumed closing travel is added when the reference has none. Use the report's actual encounter time distribution (the reference tier-list methodology defaults to about 120s ±15s) and all exact buffs, consumables, etc. If this world-side non-attacking target or front/back orientation does not causally determine selected Rust/Go engine behavior via the live handshake, FAIL. P7's **DPS** objective does not replace P4–P6's 100 consecutive-mob **seconds/mob** objective.

**P7.1 — Fixed reference reproduction; native baseline followed by engine-integration test.** Execute P7.1.1 → P7.1.2 → P7.1.3 in order. Gear, talents, rotation/APL and the saved encounter are fixed across both executions. All three steps are mandatory for P7.1 PASS; the native run does **not** substitute for the live 2D integration test.

**P7.1.1 — Saved reference configuration.** Obtain and pin the **exact saved** MythicSim report configuration, including through its **visible interactive Settings/UI** (raw JSON is optional): report ID/URL, class/spec/level/race, full gear and enchants, talents, priority/rotation/APL and conditions, buffs, debuffs, consumables and their usage, encounter target and orientation, duration/distribution, iteration and RNG policy, source/ruleset/database revision insofar as determinable, and reference DPS. Maintain a field-by-field reference inventory and record the original visible source and any uncertainties; verify that the selected Rust/Go request faithfully expresses the inventory. Do not substitute a reconstructed preset from another report. If a *material required setting truly remains unknown* after trying to inspect the saved UI, mark **BLOCKED: REFERENCE_CONFIGURATION_MISSING** and specify the missing field(s) and extraction limitation. The absence of raw JSON **alone** must never block this gate.

**P7.1.2 — Native MythicSim Rust/Go reproduction (mandatory pre-integration diagnostic).** Execute exactly the P7.1.1 saved configuration (gear/enchants/talents/APL/buffs/debuffs/consumes/encounter) in **one real pinned Rust or Go native engine**, without gsim-2D. Rust is preferred, Go equally valid. Match source/ruleset/database, saved encounter/seed and stochastic scoring, using the **approved 1,000-iteration final count** rather than blindly replaying the historical request's iteration count. No optimization or invented substitutions. Require final 1,000-stochastic-iteration **native mean DPS >= 0.99 × pinned saved reference DPS**, with compatible statistical evaluation; publish full request/output, build/config hashes and combat metrics. Native success alone is not a new production P7.1 PASS.

**P7.1.3 — Live gsim-2D ↔ selected MythicSim Rust/Go reproduction (production acceptance).** Execute the same pinned config through real interactive gsim-2D↔selected native engine, ideally the same backend as P7.1.2. Demand final 1,000-stochastic-iteration **live mean DPS >= 0.99 × saved reference** with genuine causal world→native→world trace. If backend changes, rerun native comparison on the selected backend. No standalone, fake or post-hoc PASS.

**P7.1–P7.5 universal reference tolerance (OWNER-APPROVED 2026-11-02, supersedes the P7.2–P7.4-only rule).** For the **independently discovered** winners of **P7.2, P7.3 and P7.4**, the minimum final 1,000-stochastic-iteration DPS is `DPS_winner >= 0.99 * DPS_external_reference` on the same pinned saved encounter, ruleset, native engine and scoring policy. The 1% margin now applies to all five gates' final stochastic DPS floor; all 300-second independent cold searches, legality, production live 2D causality and complete measured evidence remain in force. **P7.1 requires >= 0.99 × the pinned reference on its original fixed configuration after 1,000 stochastic iterations.** **P7.5 uses 99% of BOTH the external reference and the strongest accepted-compatible prior, with the frozen 1,000-stochastic-fight holdout mean rather than a confidence lower bound.** This permission does not waive unproven runtime integration or endorse an over-budget run.

**P7.2 — Rotation discovery.** Fix the reference's **gear and talents**. Run an **independent cold 300-second** optimization of source-legal rotation/policy; do not seed the free rotation dimension with the saved reference rotation. Each paid candidate executes through the same coupled 2D+native reference scenario. Require the discovered legal executable rotation to achieve **1,000-iteration stochastic mean DPS >= 0.99 × the pinned MythicSim reference DPS** under the same encounter and scoring policy, after low-repeat balanced-RNG candidate ranking. Publish winning policy, genuinely paid candidate count, full measurement and causal trace.

**P7.3 — Talent discovery.** Fix the reference's **gear and rotation**. Run an **independent cold 300-second** optimization of source-legal talent ranks/allocations, respecting all prerequisites/point budgets and interaction with the fixed rotation. Do not seed the free talent dimension with the reference allocation. Require **1,000-iteration stochastic mean DPS >= 0.99 × the pinned MythicSim reference DPS**, measured by the same 2D+native production pipeline after deterministic low-repeat balanced-RNG search. A fixed rotation referring to a talent-only unavailable action must be handled legally, not magically unlocked.

**P7.4 — Gear discovery.** Fix the reference's **talents and rotation**. Run an **independent cold 300-second** optimization of legal equipped gear (including items/enchants constrained by the reference rules); do not seed the free gear dimension with the reference loadout. Require **1,000-iteration stochastic mean DPS >= 0.99 × the pinned MythicSim reference DPS** measured by the same 2D+native pipeline after deterministic low-repeat balanced-RNG search. Report item IDs, whole loadout, paid candidate count and DPS evidence. (Original four-way design: baseline + three single-free-variable searches; P7.5 now adds a separate joint search.)

**P7.5 — Joint gear × talents × rotation discovery (USER-APPROVED 2026-10-28).** Run an **independent cold 300-second wall-clock** whole-build search (gear, talent allocations and rotation/policy all free) using the pinned saved reference class/spec/level/race, gear legality, encounter, buffs/debuffs/consumes and source/ruleset through a **genuinely live gsim-2D ↔ selected MythicSim Rust/Go** production integration. Never seed saved reference config or any P7.1–P7.4 winning build. Candidates must be legal, fully specified and actually executed; report paid unique count, wall time, winner gear IDs/enchants, talents, APL, engine/config hashes and world↔native trace.

**Mandatory P7.5 non-inferiority acceptance (USER-REVISED 2026-10-30; issue #10).** The independently frozen P7.5 1,000-fight stochastic holdout **mean DPS** must reach **both** (a) at least **99% of the external saved MythicSim reference mean DPS** and (b) at least **99% of the strongest *accepted and compatible* P7.1–P7.4 independently measured stochastic mean DPS**, with the SAME pinned reference encounter, source/ruleset, native engine, target, duration distribution, buffs/debuffs, consumables and scoring policy. Do not select the comparator from an unaccepted diagnostic result or mix incompatible runs:

`mean_DPS_P7.5_frozen_holdout >= 0.99 * max(DPS_external_reference, max(mean_DPS_accepted_compatible_P7.1, ..., mean_DPS_accepted_compatible_P7.4))`.

Require an independently frozen stochastic holdout of **1,000 fights** with the selected genuine native Rust/Go engine's original **stochastic** RNG, separate from balanced-RNG search evaluation. **PASS/FAIL uses the frozen holdout *arithmetic mean DPS* against both floors — no one-sided 95% confidence-bound or p95 lower-bound PASS criterion.** Report standard deviation, standard error and confidence intervals if helpful for diagnostics, but they do **not** impose additional pass thresholds. Before establishing the strongest accepted-compatible prior, verify the accepted gate decision, frozen stochastic mean, fully source-legal gear/talents/APL and matching pinned engine/encounter/duration/buffs/consumes/RNG/scoring configuration; where prior results are incompatible, rerun the accepted prior winner with matched conditions and report the new provenance. **An unvalidated native-only candidate or unresolved legality/compatibility (for example PR #23's 797.362 DPS P7.4 result) cannot automatically become the P7.5 comparator; BLOCK comparator selection if unresolved.** Never change the winner or comparator after seeing P7.5 holdout. Rediscovering a prior winner independently is legal; seeding a cold search with a reference/prior winner is not. Internal P7.2–P7.5 candidate selection uses deterministic low-repeat balanced RNG. The 300-second cold-search budget and real live 2D↔native source/legal/causal requirements are unchanged. A below-floor holdout mean is FAIL; missing comparable accepted priors or missing required evidence is BLOCKED, never inferred PASS.

**Retrospective acceptance:** Previously measured, genuinely frozen stochastic winners MAY be re-evaluated under v2.10's **mean-DPS** criterion without erasing their historical PASS/FAIL verdicts. In the historic WF613 Feral example, published P7.5 mean 848.764 DPS and reported P7.4 mean 853.931 DPS would imply a prior-relative floor of approximately 845.392 DPS, while the saved external reference was 811.024 DPS (new 1%-tolerant external floor ≈ 802.914 DPS). **These numbers are a conditional illustration, not an automatically validated comparison**: the strongest prior must be independently accepted, source-legal, and measured on compatible settings; verify raw holdout, provenance and exact accepted comparison set first. Its previous one-sided confidence-limit calculations are historical diagnostics, **no longer a PASS criterion**. Do not rescue an incomplete WF615 run or relax P7.1–P7.4 as a side effect.

**Pass reporting.** Present one shared saved reference ID/config hash and a selected genuinely coupled MythicSim Rust or Go runtime/version. Report all P7 gates with honest native and live-2D evidence; a standalone parity result does not establish live integration. Preserve owner-specific accepted historical Balance P7.1 Rust evidence without fabricating Go/2D tests. Never splice incompatible backends, scenarios or scores.
